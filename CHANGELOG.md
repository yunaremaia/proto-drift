# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed

- An ambiguous stub stem no longer produces a false HIGH `missing_sdk`. When a stub exists on
  disk but its stem matches several `.proto` files, the mapping cannot be decided, so the
  language is not claimed absent. This matches the existing rule for `orphan`, and applies to
  both `scan` and `check`.
- `check --fail-on-drift` now honours the `[fail]` config. Previously only `scan` consulted the
  gates, so the same tree, config and flag produced opposite exit codes depending on the
  subcommand. Both now go through one `_exit_code` helper.

## [0.1.0] - 2026-10-05

### Added

- `proto-drift` console script with two subcommands:
  - `scan [PATH] [--json] [--fail-on-drift]` — scan a repo for proto drift.
  - `check --proto <path> --sdk <dir> [--root <dir>] [--json] [--fail-on-drift]` — check one
    `.proto` against one SDK directory.
- Three drift detectors, all based on the working tree (no `protoc`, no network):
  - `stale` (`CRITICAL`): the mapped `.proto` is newer than its stub.
  - `missing_sdk` (`HIGH`): no stub for a language the repo otherwise ships stubs for.
  - `orphan` (`MEDIUM`): a stub whose source `.proto` is gone from the repo.
- Stub detection for Go (`*.pb.go`), Python (`*_pb2.py`, `*_pb2_grpc.py`),
  TypeScript/JavaScript (`*_pb.js`, `*_pb.d.ts`, `*_pb.ts`) and Rust (`*.rs` carrying prost's
  `@generated by prost-build` marker, so hand-written Rust is ignored).
- Stub-to-proto mapping from the `source:` path in generated headers (protoc, ts-proto), with
  a filename-convention fallback; ambiguous mappings are skipped instead of guessed.
- Optional `.proto-drift.toml` config (stdlib `tomllib`) to set proto roots, SDK roots and
  which drift types gate `--fail-on-drift`.
- Exit codes: `0` clean, `1` gated drift, `2` usage error.
- JSON output for CI, and a GitHub Actions workflow running the test suite on
  Linux/macOS/Windows across Python 3.11-3.14.

### Removed

- Version-mismatch detection, advertised by the previous README. Nothing in a generated stub
  records the proto version it was built from, so the check would have been a guess. It is
  tracked in the README roadmap instead.
- Java from the supported-languages table, for the same reason.
